# Boy - contract (provisional)

The interface between the Isaac Lab policy and the Unity rig. **This copy was written
before training**, from `boy_rig.json` as generated by `ISAAC/boy_rig/build_boy_rig.py`.
`ISAAC/scripts/export_bundle.py` overwrites it with the numbers read from the live
simulation (joint order, normaliser, evaluation) once a checkpoint exists.

Creature `Boy` · tasks `Isaac-Chase-Flat-Boy-v0` / `-Play-v0` · authored character
`Boy_Character.fbx` (Unity) = `Boy_Character.glb` (Python) · 22 links, 21 joints,
13 primitive collision shapes · 45.0 kg.

## 2. Observation vector - 75 floats

Built index-by-index in `BoyAgent.BuildObservations()`, in the order the Isaac
observation group concatenates its terms. No scaling in C#.

| idx | term | Unity source |
|---|---|---|
| 0-2 | `base_lin_vel` [m/s] | `PosToIsaac(inv(rootRot) * hips.linearVelocity)` (CoM velocity) |
| 3-5 | `base_ang_vel` [rad/s] | `AxisToIsaac(inv(rootRot) * hips.angularVelocity)` |
| 6-8 | `projected_gravity` (unit) | `PosToIsaac(inv(rootRot) * Physics.gravity.normalized)`; (0,0,-1) upright |
| 9-11 | `target_pos_b` [m] | `PosToIsaac(inv(rootRot) * (target - hips.position))` with y zeroed first, then scaled down to length 5 m if longer |
| 12-32 | `joint_pos` = q - q_default [rad] | `body.jointPosition[0] - default` |
| 33-53 | `joint_vel` [rad/s] | `body.jointVelocity[0]` |
| 54-74 | `actions` | previous raw policy output |

`target_pos_b` is the only task input. It reproduces `TargetPositionCommand._update_command`
in `ISAAC/boy_tasks/boy_tasks/mdp/commands.py`. In training the goal sat on a 3-10 m ring
and was resampled on reach (0.5 m) or after 8-12 s; there is no velocity command, the pace
(reward target 1.0 m/s) is the policy's own.

`ArticulationBody.jointPosition/jointVelocity` are radians; `xDrive.target` and the
drive limits are degrees.

## 3. Actions -> joint targets

```
joint_position_target[i] = default_joint_pos[i] + 0.5 * action[i]          # rad
tau[i] = kp[i] * (joint_position_target[i] - q[i]) - kd[i] * qd[i]           # clamped to effort[i]
```

Physics 200 Hz (0.005 s, this project's locked step), decimation 4, policy 50 Hz. Unity
runs inference every 4th FixedUpdate; `BoyAgent` logs an error (and keeps running with a
rounded decimation) if `policy_dt / Time.fixedDeltaTime` is not an integer, and never
edits the project setting itself.

Drive gains are used as radian-based (`GainUnits.Radians`) - the rung-2b play-mode test
measures the drive's actual torque per radian and fails if that ever changes.

## 4. Frames

Isaac Lab: right-handed, Z-up, X-forward, Y-left. Unity: left-handed, Y-up, Z-forward.
`Assets/unity_export/Shared/IsaacFrameMap.cs` is the one implementation.

```
M : (x, y, z)_isaac -> (-y, z, x)_unity        true vectors: position, linear velocity, gravity
-M: (x, y, z)_isaac -> ( y,-z,-x)_unity        pseudovectors: angular velocity, rotation axes
quaternion (x, y, z, w)_isaac -> (y, -z, -x, w)_unity
inertia diagonal (Ixx, Iyy, Izz)_isaac -> (Iyy, Izz, Ixx)_unity   (link frames are world-aligned)
```

Every revolute anchor's local +X is built at `-M * axis` (`IsaacFrameMap.AnchorRotationForAxis`),
so a positive Unity joint angle IS a positive Isaac joint angle. No sign is flipped anywhere.

The GLB (Y-up, faces +Z, left = +X) maps to Isaac by the cyclic permutation
`isaac = (z, x, y)_gltf`; the Unity builder verifies the imported FBX bones land on
`M * worldPosIsaac` to 5 mm and aborts otherwise.

## 5. Zero pose, default pose, and the two funny-looking axes

The articulation's ZERO pose is the authored **T-pose**: every link frame is world-aligned
there and every joint axis is one of its X/Y/Z. The DEFAULT pose (what the policy's
actions are offset from) is a joint-angle offset: shoulder roll -1.35 / +1.35 rad hangs the
arms, elbows -0.4 / +0.4, hip pitch -0.2, knee +0.4, ankle pitch -0.2.

Written in the T-pose frame, "shoulder pitch about Z" and "elbow about Z" look wrong. They
are not: the roll joint rotates the whole downstream chain by -90 deg about X (left arm),
which carries the child frame's Z onto the world's lateral axis. Once the arm hangs, pitch
about Z swings it forward/back and the elbow bends forward. The right arm mirrors, so the
left and right elbows flex with opposite signs - the table's limits encode that.

Multi-DoF joints (hips 3, ankles 2, shoulders 3) are chains of single-axis revolute joints
through 0.2 kg / 2e-4 kg.m2 intermediate links, exactly as the H1 hips are. PhysX 5 in
Isaac and PhysX 4.1 in Unity therefore see the same kinematic tree; a spherical
ArticulationBody would parameterise the joint differently.

## 6. Skin

Unity builds the physics rig from `boy_rig.json` as clean world-aligned links, then
instantiates `Boy_Character.fbx`, aligns it (trying yaw 0/90/180/270), and re-parents each
articulated bone (`hips spine thigh.* shin.* foot.* upper_arm.* forearm.*`) under its link
with `worldPositionStays`. Unarticulated bones (chest, neck, head, clavicles, hands) ride
along with their parents. The skinned-mesh renderers live under `Boy/Visual` and only need
their bone Transforms, so the mesh follows the physics for free. No ArticulationBody sits on
a bone, so no anchor compensates for an authored rest rotation.

## 7. Physics that must match

| | Isaac | Unity |
|---|---|---|
| gravity | (0,0,-9.81) | project default (0,-9.81,0) |
| ground friction | 1.0 / 1.0, multiply | any ground >= 0.8/0.6; `PM_Boy` is 0.8/0.6 **Minimum** combine, which reproduces multiply against a 1.0 ground |
| robot friction | Play: 0.8 / 0.6 (training randomised 0.6-1.0 / 0.4-0.8) | `PM_Boy` 0.8 / 0.6 |
| contact offset | 0.02 (PhysX default) | 0.02 per collider (project default is 0.01) |
| solver | TGS 4/4 | per-body 4/4 at 0.005 s (`SolverIterationMode.AutoScaleWithStep`) |
| self collision | off | every collider pair ignored in `Awake` |
| max depenetration / angular velocity | 1.0 / 1000 | per body, applied every `Awake` (Unity does not serialise them) |
| spawn | hips at z = 0.764 m | y = 0.764 m (`spawnHeight` 0.714 in the catalog; the spawner adds 0.05) |
