## A. Mass and inertia conditioning

MuJoCo puts three hinges on one thigh body and two on one foot. PhysX has no
equivalent - its spherical articulation joint is a single 3-DOF quaternion joint
whose `jointPosition` does not map back to MuJoCo's `qpos`, and whose composition
is not MuJoCo's Z-X-Y chain. So each extra hinge gets its own single-DOF link.
Those placeholders carry no geometry and no real mass; the table shows what that
costs in conditioning.

Every one of them is a placeholder, which is the benign case: an articulation is
solved in reduced coordinates (Featherstone), where a light link between two heavy
ones adds a DOF rather than a stiff constraint, and the placeholders are given an
explicit inertia tensor rather than one derived from their mass. The floor that
matters is therefore the INERTIA floor, `%.0e`, applied to all three axes of every
placeholder - not a mass floor.

**Real bodies with an inertia below 1e-04: none**


### Armature fold coefficients

MuJoCo's `armature = 0.02` adds to the joint-space mass matrix DIAGONAL,
`H[i][i] += A`. Unity exposes no such field, so it has to be bought with link
inertia - and link inertia is spatial, so it accumulates up the tree. Adding
`A*a*a^T` to every jointed link (the obvious move) over-counts every parallel-axis
run: `hip_y -> knee -> ankle_y` all turn about the same axis, so the hip would see
3A instead of A.

Placing `c_k*a_k*a_k^T` on link k contributes `c_k*(a_i.a_k)^2` to `H[i][i]` for
every ancestor i, which at the zero pose is a triangular system in c. Solved
leaf-upward it is exact, and it needs less than half the added inertia:

| --- | ---: | ---: |
| `hip_z_l` | 0.020 | 0.020 |
| `hip_x_l` | 0.020 | 0.000 |
| `hip_y_l` | 0.020 | 0.000 |
| `knee_l` | 0.020 | 0.000 |
| `ankle_y_l` | 0.020 | 0.020 |
| `ankle_x_l` | 0.020 | 0.020 |
| `hip_z_r` | 0.020 | 0.020 |
| `hip_x_r` | 0.020 | 0.000 |
| `hip_y_r` | 0.020 | 0.000 |
| `knee_r` | 0.020 | 0.000 |
| `ankle_y_r` | 0.020 | 0.020 |

`hip_x` and `ankle_x` share an axis without being a contiguous run, so the exact
solve leaves `hip_x` over-supplied by A at the zero pose only; once any of the three
Y-joints between them moves, the axes are no longer parallel and the term decays.

## C. Explicit-PD stability

The shipped actuator path applies MuJoCo's passive joint damping through the
`ArticulationDrive` (`stiffness = 0`, `damping = %.1f`), which PhysX integrates
IMPLICITLY and is therefore unconditionally stable. The diagnostic path applies the
same damping explicitly in C# through `jointForce`, where it is a forward-Euler
feedback term and stable only while

```
kd * dt / I_joint  <  2
```

`I_joint` is the composite inertia of the whole subtree below the joint, about the
joint axis through its anchor, by the parallel axis theorem. Ratios above 2 diverge;
above roughly 0.5 the joint rings and pumps momentum into its parent (PhysX 4.1 has
no compensating term, so the recoil shows up as the parent visibly buzzing).

## D. Conventions, proven

| Convention | Verdict | Evidence |
| --- | --- | --- |
| Quaternion order | **(w, x, y, z)** | residual 7.96e-08 reproducing 150 recorded observations; (x, y, z, w) is off by 8.75 |
| `qvel[3:6]` frame | **body-local** | frame-to-frame rotation axis sits 20.1 deg from omega if body-local, 62.4 deg if world (n=146) |
| `qvel[0:3]` frame | **world** | finite-differenced root position matches to 0.16 m/s against a typical speed of 1.63 m/s; the body-local reading is 14x worse |
| Linear velocity reference | **body-frame origin** | it is d/dt of `qpos[0:3]`, not of the centre of mass |

The angular-velocity one is the trap. MuJoCo stores a free joint's angular velocity
in the BODY frame, and `env.py`'s `_get_obs` applies `rot.T` to it regardless:

```python
local_angvel = rot.T @ qvel[3:6]      # qvel[3:6] is ALREADY body-local
```

So `obs[7:10]` is the angular velocity rotated into the torso frame **twice**. That
is not a defensible modelling choice, but it is what the policy was trained on for
14.5M steps, so Unity has to reproduce it exactly - `MujocoBipedAgent` applies
`Quaternion.Inverse(rootRotation)` twice and says so at the call site. Feeding the
singly-rotated value instead is silent: the vector has the same magnitude and is
only wrong when the torso is tilted, which is precisely when the policy needs it.

### Is MuJoCo's `iquat` the identity?

`robot_spec.json` ships each body's inertia as a DIAGONAL, which is the tensor in
MuJoCo's inertial frame, not the body frame. `MujocoBipedFrameMap.InertiaDiag`
permutes that diagonal and the rig builder writes `inertiaTensorRotation =
identity`, so the two frames have to coincide - and for `thigh_l` they nearly do
not: its capsule runs along `(0, 0.01, -0.38)`, tilted off the body's -Z.

Measured from the full 3x3 tensors. The recomputed PRINCIPAL moments match
`robot_spec.json` to 0.00%, which confirms the shipped diagonal is the inertial-
frame tensor. The question is how far that frame is rotated from the body frame:

* Largest body-axis misalignment - the angle between `e_i` and `I e_i` - is
  **14.31 deg** (`thigh_l`), with a largest off-diagonal term of 2.32e-03 kg.m^2, 2.386% of
  that body's largest diagonal entry.
* Treating every tensor as body-diagonal therefore costs at most **0.676%** (`thigh_l`)
  on any moment.

(The metric is `angle(e_i, I e_i)`, not an eigenvector angle, because a capsule has
two EQUAL principal moments and any eigen-solver picks an arbitrary basis inside
that degenerate plane - it will report 90 deg for a perfectly axis-aligned capsule.
A tilt within the degenerate plane is physically no tilt at all, and this metric
correctly scores it as zero.)

The identity `inertiaTensorRotation` is therefore justified - by this measurement,
not by inspection. A future rig with a genuinely asymmetric link must export
`iquat` and set `inertiaTensorRotation` from it.

The prefab ships `robot_spec.json`'s values, not the recomputed ones - MuJoCo's own
numbers are authoritative. This section exists to prove the geometry that produced
them was read correctly, so the colliders and the inertias describe one creature.
