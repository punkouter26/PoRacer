Three training pipelines that all end in one race

How a policy gets from a Python trainer into a Unity racer — three separate routes, each with its own engine, its own export tooling, and its own way of going wrong.

The three routes differ in who owns the physics. That single fact explains almost every integration problem in the project. Route A has no port problem at all — the same engine trains and races. Route B has to re-create an Isaac rig inside PhysX exactly enough that a policy trained on one works on the other. Route C sidesteps the question for Fido by shipping MuJoCo itself into the game.

The three routes, end to end

TensorBoard is not optional, and this is the rule that gets skipped. Start tensorboard --logdir results --port 6006 before every mlagents-learn launch, without exception. It goes up first so the run is observable from step 0 — a run you cannot watch is a run you cannot judge. Launch scripts must start it themselves rather than assume it is running; ISAAC/scripts/train.py does exactly that, on ISAAC/logs/rsl_rl, and tears it down last. Port 6006 must be free first: a crashed run leaks its TensorBoard, and the next launch prints "TensorBoard exited immediately (port busy?)" and then trains blind. Kill the listener; do not accept the warning. Tear down in strict order: trainer → envs → TensorBoard.

Route A — the ML-Agents loop

  1. Author the rig

    Prefab with an ArticulationBody chain, Agent_Creature, BehaviorParameters and a DecisionRequester at DecisionPeriod 20. Per-creature gait phase and amplitude tables are authored here too — they are the heuristic brain and the demo source for BC and GAIL.

  2. Sync the observation size

    PoRacer ▸ Sync Agent Observation Sizes writes VectorObservationSize = 3N + 19 onto every prefab. Skip it and the trainer rejects the env on a shape mismatch — or worse, an old .demo file does.

  3. Record demonstrations

    PoRacer ▸ Training ▸ Enable Demo Recorders In Open Scene in SCN_TRAIN_ALL, driven by the coded gait. Re-record after any observation change — a stale .demo carries the old obs size and mlagents refuses it.

  4. Build the headless env

    Builds/AllEnv from SCN_TRAIN_ALL. It contains all thirteen behaviours, so the YAML must name all thirteen or the run aborts at startup.

  5. Start TensorBoard, then train

    --env --no-graphics, explicit consecutive --base-port values, 4–8 envs to leave CPU for PyTorch. Record --num-envs: it changes batching behaviour.

  6. Export and wire

    Overwrite the .onnx in place to preserve the Unity .meta GUID, then confirm the CreatureCatalog entry still resolves.

  7. Race it, then promote it

    Editor_EloGauntlet runs actual races. Promote on ELO, never on mean reward.

Run-id conventions are 1:1 for attended runs and timestamped for unattended ones. Configs are <Name><Phase><NN>.yaml. An attended one-off pairs with run-id <name>_<phase><nn>; a script-launched unattended run is <name>_<yyyyMMdd_HHmm> instead, because it repeats. scripts/Clean-TrainingArtifacts.ps1 understands both and protects the newest run of each prefix. Prune obsolete runs before starting a new one — TensorBoard shows everything under the logdir, and dead experiments make the curve you care about unreadable. Kill TensorBoard before a --force wipe: Windows file handles will silently fail it.

Route B — porting an Isaac Lab policy into PhysX

This is the hard route, and the reason it works is that one JSON file is the single source of truth for both sides. build_boy_rig.py writes isaacbox_rig.json; boy_cfg.py reads it to configure the Isaac articulation, and IsaacBoxAgent reads the same file to build the Unity ArticulationBody tree. Joint order, default pose, stiffness, damping, effort limits and spawn height all come from one place.

What must match exactly

  • Joint order. It is the ONNX action order. export_bundle.py rewrites it from the live sim rather than trusting the authored order.
  • Frame conversion. Isaac is right-handed Z-up X-forward; Unity is left-handed Y-up. IsaacFrameMap in unity_export/Shared/ owns the conversion.
  • Control rate. policyDt / Time.fixedDeltaTime must be a whole number. IsaacBoxAgent checks this at startup and names the nearest valid fixed step in the error if it is not.
  • Drive units. Unity's ArticulationDrive applies stiffness against degrees or radians depending on version — the agent carries an explicit flag for it.
  • Observation layout. 75 floats in a fixed order, index by index.

How it is proved

  • The _PLAY Isaac config turns off all randomness — observation noise, pushes, mass and friction randomisation — so the reference recording is deterministic.
  • That recording is checked against the Unity rig frame by frame. IsaacH1 reproduces to 1 mm.
  • Independent evaluation figures ship in the rig JSON's eval block: mean speed, tracking error, falls per robot-minute, targets per minute.
  • PoRacer.IsaacPorts.Tests holds the play-mode harness.
The failure mode this route actually hit. On 2026-08-29 the assembly merge — eleven port assemblies collapsed into three — renamed the inference scripting define. Two ports, IsaacSpider and IsaacBiped2, had their policy code silently compiled out. They kept racing, brainless, for four days, because a missing policy is not an exception: it is a creature that stands still. Both were deleted on 2026-09-02. The lesson is that a compile-time define guarding inference code turns a hard failure into an invisible one — and nothing in the race loop notices a racer that never moves.
Assembly layout is fixed at six, and adding a port must not add more. PoRacer.Runtime, PoRacer.Editor, PoRacer.Tests, and PoRacer.IsaacPorts.{Runtime, Editor, Tests}. A new port joins the existing three; it does not get a triad of its own. Shared port types live in Assets/unity_export/Shared/ under PoRacer.IsaacPorts — ITargetProvider, IsaacFrameMap and MiniJson. All three were duplicated per-rig before the merge; do not re-copy them.

Route C — MuJoCo, and the one racer PhysX does not simulate

Fido is the exception to everything. He is a quadruped trained in MJX/Brax, driven by a 33→128→128→128→16 SiLU MLP read from Assets/Creature/policy.json — no ONNX, no Inference Engine. Packages/org.mujoco 3.12.0 is embedded and simulates him inside the game.

ConsequenceDetail
CreatureEntry.brainInPrefab exists He has no ModelAsset to assign, so the menu gates on HasBrain rather than model != null. Without this flag he would sit under "coming soon" forever.
ICreatureAgent.Body exists He has no ArticulationBody at all. MuJoCo moves his torso while the imported container stands at the start line — keyed off the prefab root, he would race perfectly while the camera framed an empty grid slot and every standing read row 0.
Scene build order matters Systems_MujocoWorld must create the MjScene before the first Fido is instantiated, because MjScene.Instance creates one on access.
He ignores every hazard MuJoCo cannot see Unity colliders. Mud, boost, gust and gate volumes key off attachedArticulationBody and skip him; he collides only with other Fidos.
Timestep is doubly constrained The plug-in takes MuJoCo's timestep from Time.fixedDeltaTime, ignoring <option timestep> in the MJCF. His prefab carries actionDecimation 4, so 0.005 × 4 = the exact 0.02 s he trained at. The upstream drop ships 5, correct only at its own 0.004 s.
Two patches ride on the package A GetInstanceID CS0619 fix for Unity 6.5, and an explicit PluginImporter meta on mujoco.dll. The DLL is a native plug-in: it loads at Editor startup only, so moving it needs an Editor restart.
Do not let the spawner's +0.05 m drop reach Fido. Agent_Fido.SnapToTrainedStance cancels it and puts his torso at exactly 0.34 m. Measured: 0.39 m collapses on the first stride every time; 0.34 m walks away. A trained policy has no slack for a drop a ragdoll shrugs off.

Runtime architecture — MVS over VContainer and MessagePipe

Three layers, enforced by assembly boundaries and by rule. Models are pure C# state with no Unity API. Views are MonoBehaviours that read models and forward input, with no logic. Systems are plain C# classes registered in VContainer that own and mutate models.

Why Systems_Elo needs a build callback. It has no tick or start interface, so VContainer would construct it lazily — on first resolve, which is after the first race ends. Its RaceFinishedMessage subscription would therefore not exist when it was first needed. RegisterBuildCallback(c => c.Resolve<Systems_Elo>()) forces it up front. This is the general shape of the problem: a subscriber with no lifecycle interface is invisible to the container until something asks for it.
No GameContext, no service locator, no singletons. Every class requests exactly its own dependencies — constructor injection for Systems, [Inject] Construct for Views. No FindObjectOfType, no static access. The LifetimeScope is the single place binding happens. ML-Agents Agent subclasses are the one carve-out: they take no VContainer dependencies at all, and training scenes have no LifetimeScope.

Secrets live outside the repo, at C:/Users/punko/Downloads/PoRacer-Release/. poracer-upload.jks is the upload key — losing it means losing the ability to update the app. Back it up somewhere other than this machine. Unity does not serialize keystore passwords into ProjectSettings, so both Android builders read PORACER_KEYSTORE_PASS first and fall back to poracer-upload.pass. With neither, the build aborts rather than producing an unsigned artifact.
Tools/play_publish.py needs its own venv (Tools/publish-venv). Do not install it into .venv — that one carries load-bearing ml-agents and torch pins, and the C#/Python ml-agents versions must stay in exact parity.

Headless build invocation

Unity.exe -batchmode -quit -nographics -projectPath <root> -buildTarget Android -executeMethod PoRacer.EditorTools.Editor_BuildAndroidAAB.Build -logFile <log>

Grep the log for AAB BUILD RESULT: — that line is the outcome. Do not trust the exit code: the Unity bridge reports lying exit codes, so verify artifacts rather than statuses.
